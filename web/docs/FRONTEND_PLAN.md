# Kuchi frontend migration plan

Status (2026-11-13): **S0-S2 done.** Libraries installed; every page and static section is an Astro component; the old
scripts and stylesheet are ported into `web/src`. Not yet done: turning the script-driven parts (connect panel, filters,
cards, dialog) into shadcn/React components (S3-S5), the motion pass (S6), and cutover (S7). Nothing is committed or deployed.
Owner: the UI/UX orchestrator (see `AGENT_ROSTER.md`).
A UX and trust plan is proposed in `UX_TRUST_PLAN.md` (2026-11-14). It is **not approved**: until the user approves
its section 8, the non-goals below stand and no agent builds from it.
Read this whole file before touching anything under `web/`. If this file and your memory disagree, this file wins.
If this file and the code disagree, the code wins: fix this file in the same change.

## 1. Goal and non-goals

**Goal.** Replace the hand-written HTML/CSS/JS gallery (`site/`) with an Astro frontend (`web/`) that uses
shadcn/ui components, Tailwind 4, and a small amount of motion, built to Emil Kowalski's design-engineering rules,
without changing what the site does, says, or measures.

**Non-goals (hard).**
- No backend work. No MCP server, no agent service, no data pipeline, no analytics backend.
- No redesign of copy, catalog, or product behavior. This is a rebuild of the UI layer, with polish.
- No new routes that could shadow backend routes (section 4).

## 4. Deployment safety: the three things that can hurt production

1. **Same Worker name.** `web/wrangler.jsonc` and `site-worker/wrangler.json` both declare the Worker `kuchi-site`
   on route `kuchi.kalarislabs.com/*`. Deploying `web/` therefore *replaces* the old site Worker. That is the intended
   cutover, but it means it happens on whatever deploys `web/`.
2. **`main` may deploy `web/` automatically.** `.github/workflows/deploy.yml` says Cloudflare Workers Builds deploys
   `kuchi-site` from `web/` on every push to `main`. *Not verified in the Cloudflare dashboard, confirm before merging.*
   Rule: **nothing half-migrated reaches `main`.** Work on a branch, merge a slice only when its gates pass and
   it is visually identical or better.
3. **Route precedence protects the backend, but only if we stay out of its paths.** `kuchi-agent` owns
   `/mcp`, `/mcp/health`, `/agent`, `/agent/*`, `/.well-known/openai-apps-challenge` (`agent-service/wrangler.json`).
   More specific routes win over the `/*` catch-all. So `web/` must never create pages or files under those paths.
   The old page links `agent/SKILL.md`; that link must stay a plain relative link served by the MCP Worker.

**Other deployment rules**
- `web/wrangler.jsonc` has `workers_dev: false` and `preview_urls: false`, so there is no preview environment.
  Preview locally (`npm run dev`, `npm run preview`) or ask the user before enabling previews.
- The two Workers deploy independently (separate roots, separate builds). A frontend change must never require an
  `agent-service/` change. If a slice seems to need one, stop and ask.
- Rollback: `wrangler rollback` on `kuchi-site` alone restores the previous frontend. Keep `site/` and `site-worker/`
  in git for one release after cutover so the old site can also be redeployed from source.
- After any deploy, run the read-only smoke check in section 8. It must pass before the slice is called done.
- Because another session shares this working tree, implementation agents should use `isolation: "worktree"`.
- **Agents never run `npm run deploy` or `wrangler deploy`.** `web/package.json` defines `deploy` as
  `npm run build && wrangler deploy`, which ships straight to production. Deploying is the user's call.

## 5. Stack decisions

| Layer | Choice | Notes |
|---|---|---|
| Framework | Astro 7 (installed) | Static-first HTML, islands for interactivity |
| Interactivity | React islands via `@astrojs/react` | Only where state is needed: connect panel, filter bar, dialog |
| Components | shadcn/ui 4, style `base-nova` (Base UI primitives), installed | Added **only through the shadcn CLI** (`npx shadcn@latest add <name>`), never hand-copied from memory. `button` is installed. Generated code is reviewed against section 6 (the stock button shipped `transition-all`; fixed) |
| Styling | Tailwind 4 + CSS variables | shadcn tokens in `src/styles/global.css` map onto the Kuchi palette (`--k-*`). **Preflight is off** so the ported styles keep their look; shadcn elements get the resets they need through a scoped `:where([data-slot])` rule (verified with `button`: all variants render, hydrate and press correctly). Element selectors in `legacy.css` (`a`, `button`, `h1`-`h3`, `p`) still reach inside shadcn components until that file is retired; utilities override them. The shadcn CLI needs the one-line `@import "tailwindcss"` only for `init`, not for `add` |
| Motion | CSS transitions first; **GSAP 3** for choreographed or scroll-linked animation; **Lenis 1** for smooth scrolling (user decision, 2026-11-13) | `src/scripts/motion.ts`: Lenis is on for every page except under reduced motion; GSAP loads only when `loadGsap()` is called, and then drives Lenis from its ticker. Two GSAP animations exist, both scroll-scrubbed and neither on touch screens: the hero parallax (`Intro.astro`, loaded at once on pointer desktops) and the footer parallax (`SiteFooter.astro`, loaded when the browser is idle). The footer wordmark is a canvas of animated ASCII with ordered dithering that gets bolder with the scroll (`src/scripts/ascii-wordmark.ts`, no GSAP, runs only while on screen). Click and swap motion is CSS plus the Web Animations API (`src/styles/polish.css`, `src/scripts/polish.ts`), added without editing the ported scripts. `tw-animate-css` is installed by shadcn |
| Icons | `lucide-react` (shadcn default), existing brand SVGs kept in `site/logos/` | Copy the logos as assets, do not redraw them |

Rules for adding anything: it must appear in this table, the exact version is resolved at install time and then
pinned by the lockfile, and the API is checked against current docs (Context7 or the library's own docs) before use.
Do not install libraries "to try". `web/package.json` requires Node >= 22.23.4.

## 6. Design rules (Emil Kowalski, from the installed `emil-design-eng` skill)

Installed locally at `.claude/skills/emil-design-eng` and `.claude/skills/review-animations`
(gitignored; each machine installs with
`npx skills add emilkowalski/skills --skill emil-design-eng --skill review-animations --agent claude-code`).
Both passed the skills.sh audits at install (Gen Safe, Socket 0 alerts, Snyk Low Risk).

**Decide per interaction, using frequency:**

| Kuchi interaction | Frequency | Motion decision |
|---|---|---|
| Typing in search, changing a filter or sort | Constant | None. At most an instant fade of the grid |
| Prev / next reference in the dialog by keyboard | Constant, keyboard-initiated | **None. Ever** |
| Card hover | Tens/day | Subtle, only inside `@media (hover: hover) and (pointer: fine)` |
| Grid/table toggle | Occasional | Short crossfade, <= 150 ms |
| Open / close video dialog | Occasional | Standard: ~200 ms, scale from 0.95 + opacity, **centered origin** (modal) |
| Copy-prompt toast | Occasional | Slide + fade, ~200 ms, interruptible (transition, not keyframes) |
| Featured video switch | Occasional | Crossfade, ~200 ms, optional 2 px blur to bridge the swap |
| Connect panel "More" expand | Occasional | ~200 ms, transform/opacity only |

**Non-negotiables** (a violation is a review finding):
- UI motion under 300 ms. Buttons 100-160 ms, tooltips 125-200 ms, dropdowns 150-250 ms.
- Easing: `cubic-bezier(0.23, 1, 0.32, 1)` for enter/exit, `cubic-bezier(0.77, 0, 0.175, 1)` for on-screen movement.
  These exist as Tailwind tokens: `ease-out-strong`, `ease-in-out-strong`, `ease-drawer` (`src/styles/global.css`).
  Never `ease-in` on UI. Never `transition: all`.
- GSAP follows the same rules: same curves and durations, `transform`/`opacity` only, wrapped in `gsap.matchMedia()` so
  reduced-motion visitors get no movement. Lenis must stay out of scrollable overlays (`data-lenis-prevent`).
- Pressable things get `:active { transform: scale(0.97) }`.
- Never animate from `scale(0)`; start at 0.95 with opacity 0.
- Popovers/dropdowns use `transform-origin: var(--transform-origin)`. Modals stay centered.
- Animate `transform` and `opacity` only. No width/height/margin/top/left.
- Prefer CSS transitions over keyframes for anything that can be re-triggered quickly (interruptible).
- `prefers-reduced-motion`: drop movement, keep opacity/color. Hover effects only for real hover devices.
- If removing an animation does not change how the UI feels, remove it.

Reviews of UI code use the skill's required **Before | After | Why** markdown table, one row per issue.

## 7. Quality bar from GreatFrontEnd (what was and was not available)

greatfrontend.com's homepage is an interview-prep product, and most of its content is paid. What was readable was
the free UI-component cheatsheet and playbook excerpts, so these are the practices taken from it, nothing more:

- Semantic elements. Clickable things are `<button>` or `<a>`, never `<div>`/`<span>` with a handler.
- Keyboard-only use works; focus order makes sense; focus is visible.
- Screen-reader support: ARIA roles only where there is no native element, `aria-label` on icon-only buttons,
  `aria-describedby` for errors, real `alt` text.
- Works without colour (not colour-only meaning, e.g. the old page's triangle marker) and without sound.
- Contrast and target size are checked, not assumed.
- No hard-coded labels buried inside components; labels are props. Prefer CSS logical properties.
- Build components that can appear more than once on a page, with no globals and no reliance on global state.
- Test after every feature, not at the end.
- Performance: watch re-renders and layout thrashing.

The existing site already has a skip link, `aria-live` regions, a native `<dialog>`, and labelled controls.
**Losing any of these is a regression and blocks the slice.**

## 8. Gates (every slice must pass all of them)

1. `npm --prefix web run build` succeeds (this also runs `stage`).
2. `npm run check:scope` (in `web/`) passes: the branch touched no "never edit" path.
3. `npm test` (in `web/`, after a build) passes: script boot tests, drift checks against `site/`, structure and copy
   parity of the built pages, link and route checks.
4. `npm run test:frontend` (repo root) still passes; it guards the old `site/` files. New behavior gets tests under `web/test/**`.
5. Data contract: every field the UI reads exists in the real `videos.json` / `daily-stats.json`. Types come from
   the real file, not from memory. `—` is shown for unavailable counts, as today.
6. Analytics parity: the same event names as `site/analytics-events.mjs`; no cookies, no visitor IP
   (see the `/relay` privacy rules); analytics failure must never break rendering (the existing test enforces this).
7. Links parity: `claude://`, `codex://`, Cursor, and VS Code deep links and the MCP URL
   `https://kuchi.kalarislabs.com/mcp` are byte-identical to `site/connect.js` / `site/index.html`.
8. Accessibility: keyboard-only pass, screen-reader labels, axe with zero serious issues, contrast checked.
9. Visual parity: screenshots at 390 px and 1280 px, before vs after, reviewed by the user.
10. Motion review: `review-animations` on the diff returns no blocking findings.
11. Post-deploy smoke (read-only GETs): `/mcp/health` is 200, `/agent` and `/mcp` respond as before,
    `/` is 200, `/assets/<n>.mp4` still 301s to the media domain, `/relay/config` still returns JSON.

## 10. Rules that stop agents inventing things

1. Every claim about the existing site cites `file:line`. No citation, no claim.
2. Check current documentation (Context7 or the library's docs) before using any Astro, shadcn, Tailwind, or Motion
   API. Version drift is the most common cause of invented props.
3. Add shadcn components only with the CLI (`npx shadcn@latest add <name>`), then read what was generated.
4. Do not invent data fields, event names, routes, environment variables, or Cloudflare bindings.
5. Run the build after every change you make, not once at the end. Report failures as they are.
6. Unsure? Add it to `OPEN_QUESTIONS.md` and ask the orchestrator. Do not guess.
7. Do not widen scope. A tempting fix outside the allowlist becomes an open question.
8. Stay out of the existing uncommitted work of other sessions.
